Buckets brings S3 transfers, account switching, sharing, and administration into one desktop app. It is worth evaluating if you manage S3 regularly across AWS accounts. If your current tools already handle that work well, a longer feature list alone is not a reason to switch.

This guide describes workflows to try, their requirements, and how to evaluate the price. It is written by the Buckets team, not an independent benchmark of every S3 client.

## Start with the work you do every week

Connect your AWS profile, choose a bucket, and try a small upload and download. Then test the task you repeat most often: switching client accounts, sharing a file, receiving vendor uploads, or finding an object.

| Your task | What to try in Buckets | What to check |
|---|---|---|
| Work across AWS accounts | Saved profiles and IAM Identity Center sign-in | Correct account, role, and session renewal |
| Receive files from a vendor | A Drop Zone upload page | Destination prefix, expiry, size policy, and required CORS setup |
| Recover an earlier state | Time Travel plan, review, and apply | Retained versions, complete scan, and per-object results |
| Search a large object collection | Import S3 Inventory into a local index | Report freshness, supported format, and import cost |
| Inspect S3 spending | Storage estimates and Cost Explorer | Permissions, reporting delay, and cost-allocation tags |
| Generate infrastructure code | SDK snippets and IaC export | Review the generated code and test it in your environment |

Transfer speed and task completion time depend on your network, object sizes, account configuration, and workload. We do not promise a fixed number of minutes saved.

## Authentication is supported by several clients

Buckets supports IAM Identity Center sign-in, automatic token refresh, and saved AWS profiles on Mac, Windows, and Linux. It also provides an isolated browser-based AWS CLI login flow. Expired sessions or changed organization policies can still require sign-in.

Cyberduck documents direct IAM Identity Center support in version 9.5 and later, as well as AWS CLI credentials. S3 Browser also documents a built-in SSO flow. SSO support alone is not an exclusive Buckets feature. Compare the account-selection and renewal experience you actually need. See the [Cyberduck S3 documentation](https://docs.cyberduck.io/protocols/s3/) and [S3 Browser SSO documentation](https://s3browser.com/amazon-s3-via-sso-single-sign-on.aspx).

AWS operations use the permissions of your selected credentials. Your organization should evaluate the application's data handling and release channel against its own requirements. Our [Trust Center](/trust) describes current assurance status. Signing out of the app does not automatically revoke previously shared presigned links.

## Time Travel depends on retained history

Time Travel reconstructs an earlier state from S3 object versions and delete markers. Versioning must have preserved the history you need; permanently deleted versions cannot be recovered.

1. Select the bucket or prefix and a recovery time.
2. Scan and review the proposed changes.
3. Apply the plan, then inspect the per-object successes and failures.

Each scan is capped at **200,000 version and delete-marker entries**, not 200,000 distinct files. If the cap is reached, select a narrower prefix and scan again. Bulk restore is blocked when a scan is incomplete.

Restoration creates new current versions or delete markers as appropriate; it changes the current bucket state and is not an atomic, all-or-nothing transaction. Access restrictions, retention settings, and storage classes can affect recovery. Test a representative prefix before relying on this workflow during an incident.

## Security scanning samples content

The scanner checks access settings and samples object content for supported secret and PII patterns. Defaults are up to **5,000 objects**, up to **1 MiB per object**, and skipping objects larger than **50 MiB**. Object ACL checks are optional.

Sampling can miss sensitive content, and pattern detectors can produce false positives. Findings are redacted before local persistence. Review each finding and the proposed access change before applying remediation. A clean scan is not a security certification or a substitute for an organization's broader security controls.

## Sharing, search, and analytics have different requirements

**Drop Zones** generate upload pages backed by S3 POST policies. The policies constrain the destination, per-file size, and expiry. A single configured type prefix is checked by S3; a list of allowed types is enforced only by the upload page. Declared content type is not a content inspection. Optional file-count limits are enforced by the page, not a server-side quota. Temporary credentials may shorten the usable lifetime. Saved copies of an upload page may work until their policy or credentials expire even after a hosted page is removed. See the [Drop Zones guide](/blog/dropzones-public-upload-links-for-s3).

**Upload from URL** downloads into a temporary local file before uploading to S3. It uses your disk and network; it is not a cloud-to-cloud transfer service. Source resumption depends on the remote server's range support and validators. See the [URL upload guide](/blog/upload-from-url-to-s3).

**Inventory search** queries a local index without listing objects in S3 for each query. The results reflect the imported report. Inventory generation, report storage, and import requests or transfers may incur AWS charges.

**Cost estimates** based on Standard-tier storage do not include every AWS charge. Cost Explorer has reporting delays and requires permissions; per-bucket attribution depends on cost-allocation tags. Athena, Glue, CloudFront, and other AWS integrations require their own setup and can incur additional charges.

## Decide whether the price fits your workload

Current individual plans are $9/month, $79/year, and $149 for lifetime access. Check the [pricing page](/pricing) for the applicable offer and terms.

There is no measured customer time-saving or ROI result presented here. During the trial, time a task using your existing method and Buckets, including setup, review, and retries. Record how often you perform it and whether the improvement persists after the first week.

You can estimate value as **measured time saved × task frequency × the value you assign to that time**. This is a decision aid, not a guaranteed financial return. Include the license price and any additional AWS charges, and consider whether you prefer the workflow enough to keep using it.
